# 블로그 작성 원칙

독자에게 필요한 개념, 계산, 관측 결과와 판단을 바로 쓴다. 글을 어떻게 구성했는지, 작성자가 글을 쓰면서 무엇을 하고 있는지 설명하는 문장은 넣지 않는다.

새 글과 기존 글 수정, 한국어판과 영어판에 모두 적용한다. 제목, front matter의 `description`, 도입부, 본문, 표, 표지, 그림 안의 문구, alt와 caption까지 함께 검토한다. 파일명·주소·분류·번역·시리즈는 [메타데이터 지침](post-metadata.md)을 따른다.

## 글의 내용을 바로 쓴다

- “이 글에서는 …을 살펴본다”, “먼저 …을 설명하고 다음 절에서 …을 다룬다”, “과거 사례를 바탕으로 예상 전략을 살펴본다” 같은 구성 예고를 쓰지 않는다. 제목과 목차가 이미 제공하는 안내를 본문에서 반복하지 않는다.
- 사례나 논문은 실제 내용과 논거에 바로 연결한다. 그 사례를 고른 이유나 참고하는 행위를 별도 문단으로 정당화하지 않는다.
- “이번 글을 준비하면서”, “아직 제출하지 않았다”, “현재 우리는 …을 검토하는 단계다”, “다음 글에서 소개할 예정이다” 같은 작성·진행 보고를 본문에 덧붙이지 않는다.
- 실제 연구 방법, 실험 경과, 설계 판단, 회고·에세이의 경험 서술은 글의 내용이다. 이를 글쓰기 진행 보고와 혼동해 삭제하지 않는다. 근거가 있는 연구 계획이나 전망도 내용 자체로 다룬다.

## 기술적으로 필요한 조건만 남긴다

조건을 지우면 계산, 재현, 결과의 해석이나 주장의 타당성이 달라지는지를 판단한다. 필요한 조건은 해당 수식·표·결과 가까이에 직접적인 사실 문장으로 쓴다.

- 입력 범위, 단위, 초기 상태, 허용오차, 측정 분포, 비용식의 전제는 유지한다.
- 수학적 가정, 문헌의 추정치, 실제 측정값을 구분한다. “공식 문헌의 자원 추정치”, “가정한 변화”, “한 차례 측정한 로컬 검증 시간”처럼 출처와 성격을 정확히 이름 붙인다. 추정치를 측정값으로 바꾸거나 미확인 사항을 확인된 사실처럼 쓰지 않는다.
- 예제를 “가령 …이라고 하자”로 시작했거나 표에 가정을 명시했다면, 뒤에 “실제 제출 결과는 아니다”, “새 실험을 측정한 것이 아니다”를 반복하지 않는다.
- 구현 차이, 표본 검사와 전체 검사, 로컬 검증과 hosted 결과, 계수 오차와 에너지 오차처럼 해석을 바꾸는 구분은 남긴다. 같은 한계를 도입부·본문·caption·결론에서 되풀이하지 않는다.
- 수행하지 않은 작업은 결과 해석에 필요한 경우에만 언급한다. 일반적인 주의·면책 문구로 문단을 마무리하지 않는다.

| 피할 표현 | 정리 방법 |
|---|---|
| “이 글에서는 baseline과 최적화 방향을 설명한다.” | 삭제하고 baseline의 구조나 비용부터 설명한다. |
| “위 숫자는 예제이며 실제 대회 결과는 아니다.” | 계산 앞에 가정이 이미 있다면 삭제한다. |
| “No measured competition gain”, “FeMoCo의 수치 결과는 아니다.” | 표지·그림에서 삭제하고, 입력 크기나 회로 동작을 표시한다. |
| “이번 세션에서는 이 과제를 아직 실행하지 않았다.” | 수치의 출처가 문헌이면 “공식 문헌의 자원 추정치”라고 표시한다. |
| “여기까지 확인한 것은 …이라는 점이다.” | 필요한 측정 조건과 결과를 해당 결과 옆에 직접 쓴다. |

부정문이나 “미확인”이라는 단어 자체를 금지하지 않는다. 예를 들어 scratch의 초기값, 금지 gate, binary의 소스 일치 여부는 기술적 조건이다. 불필요한 방어 문구를 지우면서 필요한 한정이나 불확실성까지 없애지 않는다.

## 자연스러운 문장과 정확한 설명

한국어는 실제로 쓰는 어순과 표현으로 다시 쓴다. 영어 문장의 구조를 옮기거나 “배경은 …에서 출발한다”처럼 추상적인 도입을 붙이지 않는다. 독자가 이해하는 데 필요한 질문과 원리, 수식·예제, 결과와 해석을 논리적으로 연결한다.

전문용어는 억지로 번역하지 않는다. `time evolution operator`, `uncomputation`, `ground-state energy`처럼 영어가 더 정확하고 자연스러우면 그대로 사용한다. 그림의 label과 수식 표기도 영어로 유지할 수 있다. 번역·문체 수정에서는 수치, 수식, 코드, 식별자와 근거의 강도를 보존한다.

표지와 그림은 회로·데이터·관계·비교를 정확히 보여 준다. caption은 입력, 연산, 축, 색, 기호와 결과를 설명한다. “설명용 그림이다”, “측정 결과는 아니다” 같은 작성자의 설명으로 공간을 채우지 않는다. 작은 예제는 `GF(4)`, `RS(3,1)`, qubit 수처럼 실제 전제를 표시하면 된다.

## 최종 편집

제목과 `description`부터 그림 안의 글자까지 한 번에 읽으며 다음을 확인한다.

1. 대상과 논리를 설명하는 문장인가, 글을 쓰는 행위를 설명하는 문장인가? 후자는 삭제한다.
2. 이 단서를 지우면 기술적 의미가 달라지는가? 달라지면 조건을 직접 쓰고, 달라지지 않으면 덜어낸다.
3. 가정·출처·측정 범위를 이미 밝혔는가? 반복 고지를 지우되 수치의 성격은 보존한다.
4. 한·영 번역 쌍과 표지·그림에 같은 메타 설명이나 방어 문구가 다시 들어오지 않았는가?
